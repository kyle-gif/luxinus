# AI 작업실과 사진 조작

2026-09-09 후속 요청: macOS/Windows의 Figma식 입력, 왼쪽 AI 채팅, 이미지·모델 선택, 제안별 비교, 앱 전용 조작 도구. 기존 로컬 LLM·Codex 로그인·원본 보호·sidecar 포맷을 유지한다. 이전 문서의 모달·텍스트 전용 설명은 이 문서로 갱신한다.

## 사용 흐름

1. 왼쪽 AI 작업 도우미에서 제공자를 고른다. Codex는 AI 설정에서 공식 ChatGPT 로그인을 진행한다. 일반 상태 표시는 로컬 요약이며 실제 연결 검사는 요청할 때 한다.
2. Codex의 **목록 불러오기**로 계정 모델 목록을 가져온다. 모델 목록을 자동 조회하지 않는다. 고급 설정은 실제 반환된 추론 강도만 보여준다.
3. **현재 사진 포함**은 기본 켜짐이다. 현재 보정·자르기·복원이 반영된 사진을 **보내기** 시점에 새로 만든다. 체크를 끄면 현재 사진을 보내지 않는다. **참고 이미지 +**로 native picker에서 참고 이미지를 더할 수 있다. 현재 사진 포함 최대 4장이고, 사진을 열거나 썸네일을 만드는 것만으로 통신하지 않는다.
4. 문장을 입력하고 **보내기** 또는 Cmd/Ctrl+Enter를 누른다. **대화만** 모드는 읽기 도구만 제공한다. **보정·앱 조작 제안**에서는 도구 호출 결과를 먼저 검토한다.
5. 제안 카드의 변경 항목과 **적용 전 / 적용 후 / 나란히 비교**를 확인한 뒤 **제안 적용**을 누른다. 비교는 저장하지 않는다. 저장 후에도 카드의 전후 상태는 해당 제안 시점 그대로다. 현재 편집으로 돌아가거나 새 보정을 하면 비교가 해제된다.
6. 고급 보정 여러 필드도 한 번의 Undo/Redo로 바뀐다. 별점·사진 표시·사진 선택·Undo/Redo는 다른 제안과 함께 실행하지 않는다. 내보내기와 로그인은 각각 설정 창을 열고 사용자가 진행한다.

대화는 현재 앱 세션의 최근 40개 메시지를 보관한다. 사진·제공자가 다르면 대화를 구분한다. 다음 요청에는 해당 대화의 최근 12개 문장과 제안 적용 상태만 추가한다. 이전 참고 첨부는 자동 재전송하지 않는다. 현재 사진 포함이 켜져 있으면 후속 요청마다 최신 사진을 새로 보낸다. 모델에 전달되는 목록에는 무작위 ID, 표시 순서, 별점·표시 여부만 있다. 목록 공유는 기본 꺼짐이며 켜면 현재 필터 목록 최대 100장을 공유한다. 파일 이름 검색어·원본 경로·EXIF·알 수 없는 sidecar 필드는 자동 전송하지 않는다.

현재 사진 이미지는 **보정 반영 축소본**이다. 공유 편집 셰이더로 렌더링하므로 화면 줌·비교 모드·마스크 안내선이 섞이지 않는다. 복원 강도가 있는데 아직 복원 결과가 없으면 이미지 전송을 기다리며 텍스트만 보내는 선택도 제공한다. 편집 상태를 별도로 전달하고 참고 이미지와 구분한다. 이미지 준비는 JPEG로 재인코딩해 메타데이터를 제거하고 긴 변을 1536px로 제한한다. 첨부 ID는 창별로 소유하고 10분 후 만료되며 전체 캐시도 제한한다. 이미지 지원이 없는 모델을 선택하면 첨부를 제거하거나 모델을 바꿔야 보낼 수 있다.

좁은 창에서는 AI와 오른쪽 보정 도구를 전환한다. 두 패널이 사진 영역을 함께 압축하지 않는다. 설정·대화·입력 영역은 각각 스크롤할 수 있고, AI 패널은 모달이 아니므로 키보드 포커스가 사진 도구로 이동한다.

## 실제 앱 도구

별도 프롬프트 이름만 추가한 기능이 아니다. Codex App Server의 `dynamicTools`를 등록하고 `item/tool/call` JSON-RPC 요청을 다음 구현에 연결한다.

| 도구 | 동작 |
|---|---|
| `luxinus_read_state` | 요청 시점의 현재 보정·앱 상태 읽기 |
| `luxinus_list_photos` | 사용자가 공유한 사진 ID·순서·별점·표시 읽기 |
| `luxinus_stage_edit` | 고급 편집 patch를 검증하고 적용 대기 상태에 보관 |
| `luxinus_stage_actions` | 앱 동작 목록을 검증하고 적용 대기 상태에 보관 |

보정 도구는 밝기·색상·자르기·수평·뒤집기·곡선·HSL·영역별 색감·마스크·노이즈 제거 강도를 지원한다. 곡선/HSL/색감의 제공한 하위 값만 병합하고 마스크 배열은 전체 교체한다. 마스크 위치는 기존 렌더러의 자른 화면 좌표다. AI 객체 자동 분할을 구현한 것은 아니다. 수평·회전은 기존 cover 렌더링 규칙을 따르며 캔버스의 90도 방향 전환과 다르다.

앱 도구는 사진 선택, 별점·표시, 필터·정렬, 목록/편집 화면, 기본/전체 보정, 자르기·부분 보정·프리셋·기록·내보내기·AI 설정·사진 정보 열기, Undo/Redo, 줌·전후 비교·밝기 경고·배경·하단 사진·사진만 보기를 지원한다. 내보내기 파일 생성, 계정 로그인, 원본 삭제·쓰기, 임의 shell·코드 실행을 자동 수행하지 않는다.

`src/shared/agent-tools.ts`는 스키마·값 범위·도구 설명·요청 지침의 단일 정의다. `src/main/agent-chat-session.ts`는 읽기/제안 모드와 누적 제안을 검증한다. `src/main/local-agent.ts`는 소유 창·사진 권한·기준 보정·sidecar 해시·만료를 확인하고 저장한다. `src/renderer/src/lib/agentActions.ts`는 승인된 동작을 실제 store/IPC에 연결하고 이전 선택·별점·필터 등 대상 상태가 달라졌으면 거부한다.

제안 준비는 파일을 쓰지 않는다. 적용은 기존 atomic sidecar 경로를 사용하고 원본 파일을 보존한다. 한 사진의 고급 편집은 완전한 편집 상태 하나로 채택한다. 보정 저장과 뒤따르는 앱 동작은 서로 다른 단계이므로 실패 시 저장된 부분과 확인이 필요한 부분을 구분한다.

## 복원 결과 저장

실제 Electron 네 프로세스로 API 저장/읽기와 UI 저장/재시작을 각각 확인했다. UI에서 기본 강도 60을 저장하고 정상 종료한 뒤, 새 프로세스에서 동일 proxy 입력과 복원 출력 해시로 캐시를 불러왔으며 추가 추론은 0회였다. 근거는 `.omc/artifacts/electron-restoration-cache-smoke.json`과 `electron-restoration-cache-ui-read.png`다.

노이즈 제거가 끝나면 보정 강도와 별도로 복원 픽셀을 앱 전용 디스크 캐시에 저장한다. 사진을 다시 열면 원본 수정 시간·크기·파일 식별자, 입력 RGBA 해시·크기, 검증한 모델과 처리 버전이 일치하는 결과를 재사용한다. 저장 실패는 현재 미리보기와 구분해 표시하고 다시 저장할 수 있다. **결과 이미지 저장…**은 현재 보정을 포함한 별도 JPEG·PNG 내보내기를 연다.

미리보기는 최대 1600px다. 원본 해상도 내보내기는 같은 NAFNet SIDD 모델로 별도 계산한다. 상세 모델 출처, 설치와 합성 화질 측정은 [노이즈 제거 문서](restoration-denoise.md)를 참고한다. 원본이나 입력이 바뀌거나 복원을 취소하면 이전 결과를 채택하지 않는다. 비어 있는 폴더로 바꾸는 동안 도착한 이전 복원 응답도 버린다.

## 제스처

Figma의 [확대와 보기](https://help.figma.com/hc/en-us/articles/360041065034-Adjust-your-zoom-and-view-options), [이동과 확대](https://help.figma.com/hc/en-us/articles/1500004414582-Pan-and-zoom-in-FigJam)를 기준으로 구현했다.

- 두 손가락 스크롤과 일반 휠은 XY 이동. Shift+휠은 가로 이동.
- pinch의 Ctrl-wheel 입력, macOS Cmd-wheel, Windows Ctrl-wheel은 커서를 기준으로 확대한다.
- Space+왼쪽 드래그와 가운데 버튼 드래그는 손 도구다. 자르기·브러시 위에서도 사진 보정을 바꾸지 않고 이동한다.
- Shift+1은 화면 맞춤. 확대는 맞춤 기준 0.1–12배다.
- 원본 잠깐 보기는 B를 누르는 동안이며 Space와 충돌하지 않는다.
- 창 포커스 상실, 포인터 취소·해제 후 손 도구가 남지 않는다.

## 검증과 제한

최종 Node/Web 타입 검사, 단위·회귀 테스트 **105/105**(실패·skip·todo 0), 프로덕션 빌드, `git diff --check`를 통과했다. 임시 데이터 기반 Electron 검사는 실제 사용자 사진을 사용하지 않았다. 초기 작업 기록은 `.omc/artifacts/ai-workspace-verification.json`, 사진 입력·복원 후속 수정 기록은 `.omc/artifacts/restoration-chat-verification.json`에 모았다.

- `npm run test:electron:viewport`: 실제 Electron 입력에서 XY/Shift 이동, Cmd/Ctrl 커서 확대, 맞춤, Space/가운데 드래그, B/blur, 자르기·브러시/원본 보존.
- `npm run test:electron:chat`: 프로덕션 UI·preload·Codex 클라이언트·앱 도구·이미지 준비·승인·저장·Undo/Redo를 연결한다. **Codex 서비스만 메모리의 합성 JSON-RPC peer로 대체**한다. 현재 사진 기본 포함·명시적 제외, 매 요청 최신 보정·자르기 이미지(640×400→480×320), 복원 텍스처 강도 혼합, 참고 이미지 전송, 1MiB를 넘는 이미지 echo와 시작 알림, 1536px·메타데이터 제거, 원본 경로 미전송, 읽기 모드, 이전 대화, 앱 배경 변경, 취소, 1440/1024 배치와 고급 설정을 검사한다.
- `npm run test:electron:agent`: 설치된 실제 로컬 모델로 한국어 수치 요청·제안·픽셀 비교·적용·Undo/Redo·저장 대기 취소·XMP/창 종료를 검사한다.
- `npm run test:electron:codex`: 실제 순수 로컬 상태 확인과 모의 계정으로 로그인 UI·늦은 응답·취소·포커스 경합을 검사한다.

AI 비교의 두 캔버스는 현재 편집 히스토그램을 덮지 않는다. 노이즈 제거 계산 결과가 없는 스냅샷은 비교에 복원이 아직 반영되지 않았다고 표시한다. 적용 후에는 기존 복원 파이프라인을 예약하며, 늦게 도착한 결과가 Undo로 되돌린 강도를 다시 덮지 않는다.

후속 실제 서비스 검증에서 GPT-6-Astra의 `code_mode_only` 도구 경로를 꺼둔 설정 결함을 재현했다. `features.code_mode_host=true`로 수정한 뒤 합성 사진의 색 인식과 실제 `luxinus_stage_edit` 호출·노출 20 제안 등록을 확인했다. 사용자 사진의 다양한 장면·필름 룩 품질과 새 OAuth UI 완료 과정은 이 검사에 포함하지 않았다. `.omc/artifacts/codex-tools-real-production.json`에 실제 서비스 결과를 기록했다. 물리 트랙패드와 Windows 실기기는 사용하지 않았고 macOS Electron에 각 플랫폼 입력 이벤트를 전달해 검사했다. 네트워크 관찰은 Node API와 Chromium 요청 범위이며 OS 전체 패킷 캡처는 아니다.

근거: [공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server), 로컬 CLI 0.153.4에서 생성한 v2 스키마. 동적 도구 API는 experimental이다. 보고서는 `.omc/artifacts/electron-chat-smoke.json`, `electron-viewport-smoke.json` 및 기존 각 Electron 보고서에 남긴다.

기존 실행 창에는 새 main/preload가 자동 적용되지 않는다. 저장을 확인한 뒤 앱을 다시 열거나 `npm start` / 개발용 `npm run dev`로 실행한다. Git 브랜치 전환·커밋·원격 변경은 하지 않았다.
